# Экспериментальный стенд

Стенд выполняет контролируемое повторное использование KV-состояний Qwen3 на MLX. Код обработки входов и разреженного пересчёта: [prepare_data.py](prepare_data.py), [backend.py](backend.py), [run.py](run.py). Результаты первого запуска приведены в [отчёте](REPORT.md).

## Входы и режимы

Полный запрос токенизируется один раз. Границы документов проверяются по offsets токенизатора; фрагменты получаются разрезанием готового массива token IDs. Ключ записи пула — SHA256 этого массива. Общая инструкция подготавливается точно; каждый документ независимо обрабатывается с позиции 0.

При сборке ключи K получают постоянный сдвиг RoPE. Выбранные позиции проходят QKV, attention и MLP на каждом слое; остальные K/V используются из пула. Маска сравнивает абсолютные позиции: `key_position <= query_position`. Весь новый суффикс вопроса вычисляется заново. Декодирование продолжается обычным путём MLX-LM.

| Режим | Вычисления |
|---|---|
| `full` | Полный проход итогового запроса |
| `no_documents` | Тот же вопрос без документов; диагностическая абляция |
| `prefix` | Наибольший точный префикс среди ранее завершённых запросов |
| `prefix_warm` | Точный префикс, содержащий все документы |
| `repair_all` | Пересчёт всех документов и суффикса через разреженный путь |
| `independent` | Независимые документы, новый суффикс без исправления документов |
| `lego4`, `lego16` | Первые 4 или 16 токенов каждого документа и весь суффикс |
| `random4-s11/s29/s47` | Четыре случайные позиции каждого документа при том же бюджете строк, что `lego4` |
| `query4` | Предварительный проход суффикса, усреднение attention по слоям и головам, top-4 внутри каждого документа, пересчёт выбранных строк |

LegoLink реализован по EPIC §4.2 на другом backend и модели. Вопросный критерий использует идею ProphetKV §4.2–4.3 с фиксированной квотой на документ и всем шаблонным суффиксом. В его стоимость входят оба прохода и вычисление оценок attention. Эталонные ответы и supporting facts доступны оценке качества; онлайн-отбор их не использует.

## Окружение и повтор инференса

Исходный запуск: Apple M4 Pro, 24 GiB общей памяти; Python 3.14.7, MLX 0.32.4, MLX-LM 0.32.2. Код инференса требует Apple Silicon. Веса Qwen3-1.7B загружаются по revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e` и преобразуются из BF16 в FP16 внутри процесса. Thinking отключён; greedy, не более 48 новых токенов.

Команды выполняются из корня репозитория:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r research/pilot/requirements.lock.txt
python research/pilot/bootstrap.py
python -m unittest discover -s research/pilot/tests -v
```

`bootstrap.py` загружает около 3,8 GiB весов, исходную таблицу HotpotQA и закреплённые источники. Опубликованные входы уже находятся в `data/examples.jsonl`. Для повторения их генерации:

```bash
python research/pilot/prepare_data.py
```

Генератор должен получить SHA256 `91b847a5d6e4ef848be0b0aac8d3c39cdc575f704129910943767e11dff0a836`. На токенизаторе и исходных данных, отличных от закреплённых версий, совпадение проверяется заново.

Опубликованные результаты защищены от перезаписи. Перед новым запуском их нужно сохранить отдельно:

```bash
mkdir -p research/pilot/results/previous-2026-11-07
mv research/pilot/results/calibration research/pilot/results/test research/pilot/results/previous-2026-11-07/
python -u research/pilot/run.py --split calibration
python -u research/pilot/run.py --split test
python research/pilot/analyze.py
python research/pilot/verify.py
```

Архивная версия исполнявшегося калибровочного файла и его конфигурация находятся в `results/calibration/source`. Их SHA256 совпадают с калибровочным manifest. Численные допуски финального запуска выбраны по [калибровке](calibration-decision.md). Для нового исследования параметры и допуск потери качества выбираются до новой итоговой выборки.

## Проверка сохранённых результатов без GPU

```bash
python -m pip install -r research/pilot/requirements-analysis.txt
python research/pilot/bootstrap.py --evaluator-only
python research/pilot/analyze.py
python research/pilot/verify.py
```

Скрипт проверки сопоставляет исходный scorer HotpotQA с опубликованными оценками всех 240 ответов, проверяет хэши исполнявшегося кода и входов, границы выборок, численные контроли и фактический бюджет по слоям. Модульные тесты механизма отдельно проверяют точный префикс, полный разреженный пересчёт, RoPE, причинную маску, сохранность пула и метрики на маленькой детерминированной FP32-модели.

## Измерительный протокол

После прогрева для каждого режима выполняются три prefill с завершением ленивых вычислений через `mx.eval` и `mx.synchronize`. Время до первого token ID включает поиск префикса или обращение к пулу, сборку, сдвиг RoPE, отбор и пересчёт. Порядок методов циклически меняется между запросами. Генерация ответа измеряется один раз на режим и запрос.

Сохраняются точные позиции обработки для каждого слоя, проход выбора, времена фаз, пик активных аллокаций, allocator cache, RSS и логический объём K/V. Подготовка уникальных записей учитывается отдельно при расчёте полной стоимости. Общая обвязка удерживает несколько пулов; её максимум памяти отличается от памяти отдельного сервера одного режима.
